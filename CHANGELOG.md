# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The file format has its own version, `schemaVersion` in [docs/SPEC.md](docs/SPEC.md), which moves independently of the extension version. Format changes are listed here under a Format heading.

## [1.0.0] - 2026-09-26

The first release. Everything below was built before any store had seen it, which is why the list is long and the version number jumps from an internal counter straight to 1.0.0: `0.0.x` was never published to anyone.

### Added

Ten pages: the product, pricing, FAQ, about us, contact us, and the privacy policy, terms of use, cookie notice and security page each at their own address. Rendered from one layout by `scripts/gen-site.mjs` and committed, so what is served is what is in the repository. It loads nothing from any other server. ADR-040, T-716

- **M6 Recovery (T-601 to T-609), after the first real session went through the product.** A tab suspender parks a tab on a page of its own and keeps the real address inside it, so an honest export records a page no other browser will reopen. TabsPack now reads the address back: The Great Suspender and its forks, Tiny Suspender, Auto Tab Discard's dummy mode and Firefox reader mode by name, and any other extension page carrying an absolute address in a parameter by shape alone. It runs before the filters on export, so dedupe and web-pages-only see the page rather than the wrapper, and at the import boundary, so files already on disk and other tools' exports are healed too. Every recovery is counted, in the export report and on the line describing an imported file, and the whole behaviour has a switch. The evidence, read from each suspender's own source, is in ADR-023
- **Restored tabs are created unloaded (T-609).** The default was to load the first twenty and unload the rest. The people who move a session between browsers have fifty to two hundred tabs, and twenty pages loading at once is the moment the browser stops answering. Every restored tab is now created unloaded except the one active tab per window, with a toggle on the options page and in the restore controls, and the old threshold kept for when it is off. On Chromium, where a tab cannot be created unloaded, the unload runs once per batch with one batch of lag, which caps how many pages are ever loaded at one time at the batch size. ADR-024
- **The cross browser matrix is a command now, not a list (T-610).** `npm run matrix` drives the Chrome, Edge and Firefox installed on the machine, and runs 26 rows on each Chromium browser and 25 on Firefox: export to a file the browser names, import, restore with bounds, groups with their colour and collapsed state, a suspended tab recovered, 200 tabs restored with unloading on, a snapshot surviving a browser restart, and the keyboard commands pressed for real with `xdotool`. Getting in differs per browser and is documented in `docs/TESTING.md` Table X4: Chrome 154 ignores `--load-extension` and takes the CDP command `Extensions.loadUnpacked` instead, Edge still honours the switch, and Firefox needs its extension uuid pinned and its own pages opened from the chrome context
- **The popup, after a first look at it in a real Chrome.** Import now sits beside export in the launcher, so the two things the product does are both one click from the toolbar. It cannot open a file picker there, ADR-009, so it opens the manager already on the import task with the file button focused. The header icon is a settings gear and opens the options page, which is what an icon in that corner is read as

### Fixed

- A file input fired no event when the same file was chosen twice, so fixing a file and picking it again did nothing
- `--border-strong`, the colour that marks the edge of a text field, was 1.58 to 1 against the page in light and 1.99 to 1 in dark, well under the 3 to 1 that WCAG 1.4.11 requires of a control's own boundary. Found by the contrast check on its first run, and fixed in both themes
- **Two defects the matrix found in the restore, both serious, both Chromium (T-611).** A tab unloaded before its navigation committed lost its address permanently: it came back blank and clicking it did not bring the page back. And Chromium gives a tab a **new id** when it unloads it, so every id the engine held afterwards was stale, which silently cost the group, the opener relationships, the muting and the active tab of every restore that unloaded anything. Both were measured in a real browser, both are fixed, and the fake browser models both, so the unit suite now fails without either fix. The older default hid the scale of it: before unloading became the default, the same loss hit every tab past the twentieth, so a 200 tab restore came back with 20 pages and 180 blank tabs. ADR-025
- Firefox loads a pinned tab straight after agreeing to create it unloaded, so the report could claim more unloaded tabs than there were. The count is recounted from the browser at the end
- `adapter.discardTabs` counted every tab it asked the browser to unload, including the ones the browser refused. It answers with what it actually unloaded now, and the restore report counts those
- **The defect the matrix still missed, found by a real session (T-612).** The fix above waited for a tab to report an address before unloading it, and accepted `pendingUrl` as that address. `pendingUrl` is the address a tab is *on its way to*, so it is proof the navigation has **not** committed, which is the exact state that destroys it. Every restore row in the matrix and the smoke run points at a port nothing listens on, where a connection is refused in under a millisecond and the address is already committed by the first poll, so the difference never showed. On a real 50 tab session of Gmail, Docs and Instagram, **47 of 48 restored tabs came back blank**: no address, no title, and no way back to the page. Only a committed `url` counts now, and a tab that has not committed by its batch's deadline is carried to the end and then left loaded rather than unloaded, because memory is a cost and a lost address is a lost page. Measured after the fix on the same session: 48 restored, 0 blank, 46 unloaded in Chrome and 44 in Edge, in 15 and 21 seconds against the 1.3 seconds it used to take to lose them. Two new guards: the fake browser now reports `pendingUrl` while a navigation is in flight, with `commitReads` for how long, and the matrix serves 24 pages itself on a real socket with a 400 ms delay and asserts that not one address was lost. ADR-026
### M7, from a real user's first proper session

A review after the user ran TabsPack on their own tabs in three browsers. Every
item below came from that session.

- **A successful export no longer looks like a failure (T-701).** The report turned amber with a warning triangle whenever a filter had removed anything, and Remove duplicates is on by default, so an ordinary successful export came up looking like a problem. A written file is a success; what the filters removed is detail, in the muted line where it already was. ADR-029
- **Group names were being lost on export, silently (T-702).** Without the optional `tabGroups` permission the `browser.tabGroups` namespace does not exist at all, so the collector never reads a group's title or colour and the file carries bare membership. Tabs came back in the right clusters with no names. The permission was only ever offered on the **import** side, so a user who only exports never saw the offer and never found out. It is now offered on the Export pane, before the file is written, and an export whose groups have no names says so in its report. ADR-030
- **The permission notice is a callout now (T-703).** It was an inline row at the bottom of a card, underneath a tree of fifty rows. It is a banner at the top of the pane: coloured bar, glyph, one sentence, one button. A browser will not show its own permission dialog without a click of ours, so that click has to be impossible to miss. ADR-031
- **Export defaults changed, and one switch was lying (T-704).** Titles are on by default, because the only reason to export as text is to read it. Favicons are off: measured at **7 to 9 percent** of a real file, and nothing reads them, not the preview, not a restore, not the browser. And clearing the box labelled "Favicon URLs" used to remove only embedded icons while keeping every remote one; off now means none. ADR-032
- **The import screen gets out of its own way (T-705).** The drop target folds to a summary line once a pack is loaded, with one button back to it.
- **An import that showed no list (T-706).** Reported once and not reproduced in fifteen consecutive attempts across three real packs in a real Edge. Two ways it could happen are gone: the preview is revealed **before** the tree measures itself, since a virtualised list cannot measure a box that is `display: none`, and every failure in the read now reaches the screen instead of becoming an unhandled rejection, which is exactly the reported symptom. The cause is not confirmed. ADR-031
- **The toolbar reports what happened, from anywhere (T-707).** It used to be a bare count in one colour, set only by an export from the popup; an import set nothing, so a two hundred tab restore could finish behind three windows with no sign of it. The badge now carries a tone, blue while working, green with a count, red `!` on failure, and the tooltip carries the sentence: "Exported 42 tabs to tabspack-20260926-0915.tabspack.json". Popup, manager page and keyboard commands all go through one module. The unused `badgeMs` setting is gone. ADR-033
- **"Unloaded" is "asleep" (T-708).** The browser's word replaced by one people use. Not "suspended", which in TabsPack already means a third party suspender's wrapper page, two panes away.
- **`npm run pack` (T-709).** Every archive in `dist/artifacts/`: Chrome, Edge, the Firefox `.xpi` and the source zip AMO asks for, built from `git ls-files` so nothing ignored can leak into a public archive. Release Firefox refuses any unsigned extension and says only "appears to be corrupt", so the two routes that actually work are now written down. ADR-034
- **A Support pane (T-710).** Pick what it is about, say what happened, optionally leave an address. The message is composed in core, shown on screen in full, and handed to your own mail client: the extension makes **no network request**, so "nothing leaves your device" stays true as written, and no API key ships, because a key inside a published extension is a key anyone can read. The diagnostics are five lines you can read and switch off, and nothing about your tabs is in them, which is a test rather than a promise. ADR-035
- **A rating ask that stops (T-711).** Earned by finished exports and restores rather than days installed, shown after the work rather than during it, three answers of which two end it, and at most three asks in a lifetime. An unpacked build has no store page, so it shows nothing at all. ADR-036
- **Four icon candidates (T-713).** `npm run icons:compare` renders every one at 16, 32, 48 and 128 in both themes and in a toolbar. The first three drafts were thrown away after that sheet showed them reading as a folder, a briefcase and a plus sign at 16 pixels.
- **Two bugs the phase audit found in its own work.** The rating ask built its Chrome store link out of the runtime extension id, which every unpacked build also has, so a development install linked confidently to a Web Store page that did not exist; the store listings are written down in one place now and are empty until something is actually published, so nothing is shown at all. And both new features opened an address through `openExtensionPage`, which resolves against the extension's own origin, so a `mailto:` became `chrome-extension://<id>/mailto:...` and opened nothing. `openExternal` is the method for an address that is not ours. ADR-036 and ADR-038
- **Built and maintained by palworks.ai (T-714).** One quiet line at the foot of About, under the privacy paragraph, as a link the user clicks and never anything a page loads. ADR-037

- **CI was red on node 20 the first time it ever ran.** `package.json` promises node 20 and three build scripts imported `glob` from `node:fs/promises`, which landed in node 22, so the lint step died at import time before running a single rule. The handful of patterns those scripts use are matched by `scripts/lib/walk.mjs` now, and the whole suite was run on a real node 20 to prove it: lint clean, 229 tests, 21 fixtures

- **One page instead of two (T-511).** TabsPack had a manager page and a settings page with the same header and the same cards, and counting them control by control, the settings page was mostly a second set of widgets over the same stored values: **fifteen of them**, all writing the same settings and kept in sync at runtime. They are now one document with a rail of five: Export, Import, Snapshots, then a hairline, then Settings and About. A setting that belongs to a task lives with that task and is saved there; Settings holds only what belongs to none, which is suspended tab recovery, restore speed, theme and reset. `options_ui.page` is `manager.html#settings`, and Chrome 154, Edge 153 and Firefox 156 were each measured accepting a fragment there and landing on the right pane, so no redirect page was needed. The address follows the pane, so a reload comes back where you were. Below 900 px and at 200 percent zoom the rail becomes the strip the page used to have, with no script. The export scope gains **This tab**, which used to be reachable only from a dropdown on the settings page. Nineteen message keys removed, seven added, and the settings copy rewritten in plainer words. A smoke check now asserts the property rather than the diff: no control on the settings pane appears on another pane. ADR-028

- **And the same defect again on Firefox, found by the fix above (T-613).** The Firefox matrix then failed one run in four, and rebuilding that row to print the tab strip turned it into two failures every run and named two defects. Firefox refuses `tabs.create({ pinned: true, discarded: true })` with "Pinned tabs cannot be created and discarded", and the engine's probe read that single refusal as a verdict that Gecko could not create unloaded tabs at all, so **one pinned tab in a pack downgraded every tab after it** to the create then unload path. Those tabs then reported `about:blank` while navigating, which is not an empty string, so the guard added an hour earlier let the unload through and lost the address exactly as before. A pinned tab now never asks to be created unloaded on any engine, and `about:blank` counts as an address only for a tab that asked for it. Three consecutive Firefox runs at 25 of 25 rows, where two of six failed before. The matrix gained two rows that would have caught it: 40 tabs created unloaded, and every one of the 200 addresses of a large restore checked rather than only the count. ADR-027
- The manual matrix in `docs/TESTING.md` still said the clipboard is written from an offscreen document on Chromium, which ADR-021 removed. Two stale test counts corrected against what the suites report
- The dark screenshots in the browser smoke run were taken inside the 120 ms colour transition, so a button still wore its light text and border and the shot read as a theme bug that was not there. The run waits for the transition now, and asserts a button's own ink and border in dark rather than trusting the page background
- Four defects a real browser found and no unit test could: `tabs.create` rejects the `title` property on Chromium, a `display: flex` rule defeated the `hidden` attribute, `tabs.group` needs no permission although its titles and colours do, and the preview silently deselected the tabs it was supposed to report

### Audited

A sweep of the whole codebase for dead code, gaps, races and claims the code does not keep.

- The runtime message router in the background was dead: every TabsPack page has the extension APIs itself. It is gone, with `sendMessage`, `onMessage` and the `UNHANDLED` sentinel, and `docs/ARCHITECTURE.md` section 7 now explains why contexts do not talk to each other
- Two settings written in the same millisecond lost one of them. Writes are serialised now
- A page that threw while wiring itself looked ready and did nothing. Every surface reports a failed start
- Selecting in a five thousand tab tree counted every descendant of every visible row, on every scroll. Counted once, kept, and the preview renders in about fifty milliseconds
- A refused storage write, which is what a full quota looks like, was an unhandled rejection with nothing on screen
- Bounded what was unbounded: the largest file the importer will read, the number and length of exclude patterns, and the number of issues one file can put on screen. All five limits are in `docs/LIMITATIONS.md` Table L5

### Measured

- NFR-001, on the built package in a real Chromium with 200 tabs open: the popup is interactive in 38 ms, median of ten runs, against a 150 ms budget
- NFR-004, restoring 200 tabs into four windows: no single block of the interface at all, against a 200 ms budget, over a 3.5 second restore
- NFR-005: a 5000 tab pack previews in 70 ms once the page is open, about a second from a cold page load, with roughly thirty rows in the document
