# Store listings

One listing, written once, submitted to three stores with the differences each
one forces. Task T-505.

| File | For |
|---|---|
| [../../store_listing.md](../../store_listing.md) | **What to paste into a dashboard**, field by field, in the order it asks: name, summary, description, permission justifications, privacy answers, artwork, and what to do after each store accepts it |
| [listing.md](listing.md) | The longer prose about the product that the listing draws on |
| [submission.md](submission.md) | What each store asks for at upload time, the answers, and where the current version stands: Table T5 is the pre-submission gate and Table T6 is what is actually blocking each store |
| `../../assets/store/` | The store icon, five screenshots and both promo tiles from `npm run store-art`, and Edge's logo from `npm run assets`. [assets/store/README.md](../../assets/store/README.md) lists every file |

Screenshots are pictures of the real interface, taken by `npm run smoke`, which
writes them to `.tmp/shots`. Take them on a clean profile with a believable
session open, never with real browsing in the frame.

The permission answers come from [PLAN.md](../../PLAN.md) Table P8 and must not be
improvised at upload time. If a reviewer asks for something these files do not
answer, that is a decision to record, not a sentence to invent: PLAYBOOK section 8.
